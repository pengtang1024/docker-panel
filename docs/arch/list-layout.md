# 统一列表化 + 容器台账内联树（方向 D）

> 隶属 [architecture.md 总纲](../architecture.md) 与 [ui-interaction.md](ui-interaction.md)。
> 本文是「全部内容区列表化 + compose 层级内联」的权威设计文档。
>
> 决策来源：用户 2026-10-21 复核上一版（Compose 左侧栏树）后要求
> **「不应该有左侧栏，而且应该所有的内容区都是列表形式」**。
> 上一版的左侧栏树方案整体作废（代码已在 `develop` 落地，随本设计回退）。

---

## 1. 目标与非目标

**目标**

- **撤掉左侧栏**：compose 层级不再由独立导航栏承载，改在容器列表内部表达。
- **所有内容区都是列表**：容器 / 镜像 / 网络 / 卷四个视图统一为**表格列表**，
  镜像 / 网络 / 卷不再用卡片网格（两种形态并存本身就是割裂感）。
- 保留密集台账的既有价值：列起点固定、可竖着扫读、虚拟化。

**非目标**

- 不做侧栏宽度拖拽 / 折叠（没有侧栏了）。
- 不做三级树（项目 → 服务 → 容器 三层嵌套）；树最多 **2 级**（见 §3.2）。
- 不做项目 / 服务级批量启停（另开一期）。
- 不做表格的行内多选批量（容器视图的批量操作保持现状）。

## 3. 容器视图：台账内联树

### 3.1 行模型

一行 = 三种行型之一（`kind` 字段区分）：

| kind | 行型 | 内容 | 高度 |
|------|------|------|------|
| 0 | 容器行 | 状态点 / 名称 / CPU / 内存 / 磁盘 / 镜像 / 端口 / 行内操作 | 30px |
| 1 | 项目带 | 展开箭头 + 项目色点 + 项目名 + 容器数 + **资源汇总**（**通栏分节**，镜像 / 端口列留空） | 28px |
| 2 | 服务带 | 展开箭头 + 服务名 + 容器数 + **资源汇总**（缩进一级，通栏分节） | 28px |

项目带 / 服务带**通栏**（整行背景 + 左侧 2px 项目色条），容器行的列起点**不受影响**
——分节带是行列表里的一行，不参与列宽计算。

### 3.2 树的深度：1-2 级

- **项目带**恒定出现（level 1）。
- **服务带**仅在**该服务下有 ≥2 个容器**时出现（level 2）；只有 1 个容器的服务
  直接把容器行列在项目带下面（level 1），不套一层空壳。

```
▾ ● live-games (5)              ← 项目带
    live-service-1               ← 容器行（缩进 1 级）
    live-service-2
    ▾ web (3)                    ← 服务带（缩进 1 级，仅多容器服务才有）
        web-1                    ← 容器行（缩进 2 级）
        web-2
```

> 这样在「一服务一容器」的常见 compose 项目下，树只有 1 级、列表依然紧凑；
> 真有多容器服务时才展开第 2 级。层级信息不丢，但不产生一堆 1 子项的壳。

### 3.3 展开状态

- **默认全部展开**（首屏仍能看到容器行，不像全折叠那样把内容藏起来）。
- 展开状态按组键持久化：`project:<名>` / `svc:<项目>/<服务>`。
- 点带上的箭头 = 展开 / 收起；点带上的名字 = 展开 / 收起（同一动作，不做筛选）。
  → **树的分组不是筛选器**：不引入「只看某项目」的范围状态。

### 3.4 列与排序

- 台账列去掉**项目列**（项目带已经承载了归属，项目列是纯冗余）。
  保留：状态点 / 容器名 / CPU / 内存 / 磁盘 / 镜像 / 端口 / 行内操作。
- **排序在组内生效**：排序字段（名称 / CPU / 内存 / 磁盘 / 状态）决定**每个组内部**
  容器的顺序；组之间的顺序按组名稳定排列。
  → 树结构决定「谁在谁下面」，排序字段决定「组内怎么排」，两件事不打架。
- 容器行按层级缩进（名称列内容右移 `18px × depth`），**列起点不变**。
- 分组带的名字落在 `44px + depth*18`（箭头 14px + 色点 18px + 间隙），
  与**同层**容器行的名称列起点逐像素对齐——层级只靠缩进表达。

### 3.5 计数口径

概览带（容器 / 运行中 / 已停止 / 需关注 + CPU TOP4）与筛选栏 chips 的计数
= **当前可见（展开后）的容器集合**。折叠一个项目 → 计数同步变小，
保持「概览带数字 = 列表行数」这条既有不变量。

### 3.6 分组带的资源汇总（成员之和）

分组带不只显示名字与成员数，还显示**该组的资源汇总 = 组内成员之和**，
落在台账的 **CPU / 内存 / 磁盘** 列上（与容器行同 x，见 §3.4 的列起点契约）。

| 列 | 汇总口径 |
|----|----------|
| CPU | 组内**运行中**成员的 `cpu_percent` 之和（停止的容器没有实时占用 → 不计；一个运行成员都没有时显示「—」） |
| 内存 | 组内**运行中**成员的 `mem_usage` 之和（同上，无运行成员显示「—」） |
| 磁盘 | 组内**全部**成员的 `size_rw` 之和（可写层占用是累计值，停止后依然成立） |
| 镜像 / 端口 | 不适用 → 留空（保持列起点） |
| 操作列 | 容器数（右对齐） |

要点：

- **汇总描述的是「这个组占了多少」，与组是否展开无关** → 收起时数字照旧
  （汇总按组成员累加，折叠只是不渲染子行）。
- **微条用分组自己的基准**：行的微条按「单容器最大值」归一；分组是**总和**，量级天然更大，
  共用行的基准必然永远满格 → 分组带按**各分组总和的最大值**归一（`group_totals::max_base`），
  组与组之间可直接比大小且不会溢出。
- 项目带汇总 = 该项目**全部**容器之和（含服务带下的容器）；服务带汇总 = 该服务自己的容器之和。
- 带行虽然通栏，但**必须镜像 `ledger-row.slint` 的列结构与列宽**（同一套 `LedgerCols` +
  父级下发的同一组 `name_w` / `image_w` / `show_disk` / `show_ports`），
  否则汇总值与容器行的数值列对不上号。
  ⚠️ 改 `ledger-row.slint` 的列结构时必须同步改 `ledger-tree-row.slint`。
- 实现：`src/ui_rows/group_totals.rs`（`GroupTotals::of(members)` 累加 +
  `cpu_text` / `mem_text` / `disk_text` 格式化 + `max_base` 微条基准），
  结果写进分组行的 `cpu_text` / `mem_text` / `disk`（复用容器行的同名字段）与
  `cpu_ratio` / `mem_ratio`。

## 4. 镜像 / 网络 / 卷：表格列表

### 4.1 列（精简列）

| 视图 | 列 |
|------|-----|
| 镜像 | 名称（`repo:tag` 单文本） · 大小 · 创建时间 |
| 网络 | 名称 · driver · 子网 |
| 卷 | 名称 · 大小 · 挂载点 |

（层数 / scope / 关联容器数 / 匿名标记等次要信息移到详情抽屉，不进表格。）

镜像的名称列用 **`repo:tag` 单文本**而不是「名称 + tag 芯片」：
芯片与名称分离后（芯片右对齐在列尾）会与名称脱节，读起来像两列。
其余 tag 在抽屉详情里看。

### 4.2 排序

- 每个列表有**自己的表头**，可点列头排序（同列再点翻方向），与容器台账一致。
- 排序状态按视图独立保存（切视图回来保留）**并持久化**到配置文件（重启恢复）。
- 排序字段：镜像 = 名称 / 大小 / 创建时间；网络 = 名称 / driver / 子网；卷 = 名称 / 大小 / 挂载点。
- 状态在 Rust → Slint 之间**打包成一个 int**（低 3 位 = 列下标，第 3 位 = 降序标记）；
  Slint 侧用 `Math.mod(x, 8)` / `x >= 8` 解包（Slint 1.18 不支持 `%` 与 `&` 运算符）。
- 排序方向箭头：左对齐列**跟在标签后面**（不占布局宽度 → 列起点不变）；
  右对齐列用**覆盖层**放在列左端（值仍然右对齐，列起点不漂移）。

### 4.3 其它

- 行高 30px，与容器台账一致；虚拟化渲染（@material ListView）。
- 保留行内操作：镜像（运行 / 删除）、网络（删除）、卷（删除）。
- 空态复用现有 `EmptyState`。

## 5. 状态与数据流

| 状态 | 归属 | 写入方 | 读取方 |
|------|------|--------|--------|
| 收起的分组键集合（`project:*` / `svc:*`） | `AppState.compose_collapsed` | `callbacks_compose.rs`（UI 回调，UI 线程） | 行构建（`ui_rows/compose_tree.rs`） |
| 三个列表的排序字段 / 方向 | `AppState`（`sort_images` / `sort_networks` / `sort_volumes`，类型 `ResourceSort`） | `callbacks_sort.rs`（回调写，同模式） | 行构建 + 表头高亮 |
| 台账排序字段 / 方向 | 既有 `sort_field` / `sort_desc` | 既有回调 | 组内排序 |

纪律不变（AGENTS.md 规范 #18）：**用户操作过的状态只由回调写**，consumer 只刷数据；
行模型用 `rows_epoch` 判定过期。

展开状态的存储口径：存「**收起**的分组键」集合，**不在集合里 = 展开**
→ 新出现的分组默认展开，不需要额外的「已展开集合」初始化。

## 7. 风险与既有约束

| 风险 | 处置 |
|------|------|
| **行模型从 1 种变 3 种** | `kind` 字段 + delegate 内分支；带行独立组件（`ledger-tree-row.slint`），不把 `ledger-row.slint` 撑爆（现 229 行，逼近 300 上限） |
| **带行通栏 → 列起点漂移** | 带行不参与列宽计算；容器行的列宽仍由 `LedgerCols` 统一下发（规范 #20 不变）。带内的**汇总值**例外：它镜像 `ledger-row.slint` 的列结构，与容器行同 x（§3.6） |
| **分组汇总画微条会满格** | 分组带用**自己的基准**（各分组总和的最大值），不共用行的单容器基准（§3.6） |
| **计数与列表不一致** | 概览带 / chips 计数一律取「展开后可见集合」，与列表行数同源 |
| **列表行模型复用 render 缓存** | `render.rs` 的 CachedModel 差量同步按行比对；行型混合后 `PartialEq` 仍可用（struct 派生） |
| **镜像层数 / 卷大小回填是异步的** | 回填消息到达后重建对应列表行（既有 Msg 通路：`ImageLayers` / `VolumeSizes`） |
| **R2 300 行上限** | 新增文件按职责拆；`ui/cards.slint` 删除后总量下降；`src/ui_rows/containers.rs` 行构建变复杂 → 树行构建单独成文件；`ui/app.slint` 拆分后正文 294 行（去掉侧栏时代遗留的空 `body-row` 包裹层 + 色板应用抽成回调） |
| ~~卷「大小」列取不到值~~ | ✅ **已修**：bollard 0.21 的 `SystemDataUsageResponse` 只建模废弃的 `VolumeUsage` 键，而守护进程返回 `Volumes` 数组 → 改走裸 HTTP 请求（`docker/raw_http.rs`）自己读 `Volumes` 键，卷大小与按大小排序恢复正常 |

## 8. 验收标准（✅ 已实测）

1. **无左侧栏**：容器视图左侧没有侧栏，列表通栏。✅
2. 容器列表出现项目带（通栏分节 + 色点 + 计数 + 箭头），容器行缩进在带下面。✅
3. 点箭头展开 / 收起；收起后该组容器行消失，概览带与 chips 计数同步变小（9 → 3）。✅
4. 多容器服务出现服务带（level 2），单容器服务不出现。✅
5. 台账列起点逐列不变（MCP `get_element_tree` 比对）：表头与各行同
   `44 / 445 / 583 / 647 / 719 / 1056`。✅
6. 镜像 / 网络 / 卷视图是表格列表，表头可点排序，方向可翻转；行内操作可用。✅
7. 展开状态与三个列表的排序状态持久化，重启恢复（`config.json` 里
   `compose_collapsed` / `sort_images` / `sort_networks` / `sort_volumes`）。✅
8. 分组带显示**资源汇总（成员之和）**：项目带 `2.6% / 2.0G / 7M` =
   组内成员之和（CPU 只算运行中成员，磁盘算全部成员）；收起时数字照旧；
   汇总值与容器行的 CPU / 内存 / 磁盘列**同 x**（`445 / 583 / 647`）。✅
9. 门禁全绿：`cargo fmt --check` / `clippy -D warnings` / `cargo test`（30 passed）/
   `cargo build --release --locked`；旧项目名零残留；所有新增/改动文件正文 ≤300 行。✅
