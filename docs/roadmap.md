# 路线图

> **一句话**：这里只写「已经想清楚的方向」和「明确不做的事」，不给日期承诺——排期随实际可用时间变化。
> **相关页面**：[已知限制](../README.md#6-已知限制) · [更新日志](../CHANGELOG.md) · [架构设计](architecture.md)

## 1. 这份路线图怎么读

| 分节 | 含义 | 你可以期待什么 |
|------|------|----------------|
| 当前阶段 | 已经交付、正在维护的能力面 | 可以直接用，遇到问题按 [troubleshooting](troubleshooting.md) 排查 |
| 候选方向 | 想清楚了、但**未排期**的功能 | 提 issue 表达需求会影响优先级，但**不构成承诺** |
| 明确不做 | 与项目定位冲突、或不打算承担的方向 | 不必再提；确有强需求请先开 issue 讨论定位 |

> [!NOTE]
> 本项目是单人维护的小工具，路线图按「先把现有能力做稳」排序：修缺陷与补文档优先于加新功能。

## 3. 候选方向（未排期）

按「对现有用户的实际收益」粗略排序，**不代表实施顺序**：

| 方向 | 现状 | 说明 |
|------|------|------|
| 镜像 / 网络 / 卷的批量操作 | 只有容器视图支持多选 | 需要先统一三个资源列表的行模型与操作入口 |
| Compose 导入 / 导出 | 只有台账内的 Compose 分组展示 | 涉及 compose 文件解析与状态回写，工作量大于展示层 |
| 定时清理（prune 计划任务） | 只有手动清理弹窗 | 与「空闲零请求」的设计取向需要对齐 |
| 远程 Docker 连接 | `DOCKER_HOST` 只识别 `unix://` | tcp / ssh 需要重做连接层与 TLS 假定 |
| 镜像行 ▶ 直接运行 | 当前只回显提示 | 需要容器创建表单，属新界面 |
| 更细的日志检索 | 只有跟随与复制 | 大窗口下的按关键字过滤涉及索引与重排策略 |

## 4. 明确不做

| 不做的事 | 原因 |
|----------|------|
| 非 Wayland 显示后端的适配代码 | 项目定位在 Linux 桌面，不为其它后端单独加 feature 或代码路径 |
| Electron / Node / WebView 外壳 | 与「Rust 单二进制 + Slint 原生 GUI + 纯软件渲染」的定位冲突 |
| GPU / Vulkan / GL 渲染路径 | 纯软件渲染是「零 GPU 依赖」的前提，也是 deb 不依赖 libgl1 的原因 |
| 定时兜底轮询刷新列表 | 会掩盖 `/events` 的真实缺陷，见 [threading.md](arch/threading.md) |
| 内置 Docker 守护进程管理（安装 / 升级 dockerd） | 越界到系统包管理，出错面远大于收益 |
| 遥测 / 使用统计 | 工具本身不需要，也不希望引入数据出境面 |

## 5. 怎么影响路线图

- **表达需求**：在 [GitHub Issues](https://github.com/pengtang1024/docker-panel/issues) 或 [Gitee Issues](https://gitee.com/pengtang1024/docker-panel/issues) 开一条，说明场景与当前替代做法；重复需求会被合并到同一条。
- **想直接做**：见 [CONTRIBUTING](../CONTRIBUTING.md) 的「第一次贡献」，从 `develop` 切分支提 PR。
- **报缺陷**：走 [bug 模板](https://github.com/pengtang1024/docker-panel/issues/new?template=bug_report.yml)；安全相关问题请**不要**开公开 issue，按 [SECURITY](../SECURITY.md) 私下报告。
